# 05 — 高频陷阱与交付前验证清单

## 1. 十大高频陷阱

1. **稀疏采样漏关键动作**：掰头、伸手、换人可能只有 3–5 帧。稀疏网格只建假设，转折区间必须密帧裁决。
2. **拍摄者透明化**：把第一人称拍摄者当纯机位，漏掉只露袖子/车头/手的第三行动者。铁律：有目的运动的非身体物体必有控制者。
3. **BPM 误检当配乐**：随机 onset 会被算法报成稳定 BPM。频谱 kick 网格 + onset std/mean + RMS 周期性三证，否则判无 BGM。
4. **后期特效当现场动作**：定格/白闪/漫画线/拟声字进 `editing` 与 `overall_soundscape`，不进动作时间线。
5. **先验剧情捕获（最致命）**：用最常见模板收敛后所有证据都被收编成佐证。对策：骨架阶段并列多候选，密帧判别，不选最省事的故事。
6. **水/液体没有来源与方向**：先有蓄力喝，再沿受力方向喷；喷在透明还是镀膜面罩上决定路径，物理不通回查帧。
7. **动作之间中性复位**：相邻动作用残余动量衔接，禁止回中性姿势再开始下一个。
8. **空泛质量词**："高质量/电影感/好看"无法执行，删除或换成可拍的光色材质运动。
9. **角色中段漂移**：subject 锁定 + physics 演化 + negative 三重固定发色/眼镜/衣物/面罩状态。
10. **换角色顺手改剧情**：时间戳/动作/运镜/剪辑/声音零改动，必要连带改动全部进对照表。

## 2. 认知层自检

- 结论是"像素必然推出"还是"高概率模板"？后者必须找反证。
- 这个动作的发起者是谁？画里那只手/物体受谁控制？
- 换一个剧情假设，这批帧是否同样成立？成立则密帧裁决或提问。
- 音频能量峰和每个关键动作是否一一对账？
- 是否把"没看清"误写成"没发生"？

## 3. 交付前验证清单

### 证据层
- [ ] ffprobe 建档完整（时长/画幅/帧率/音轨）
- [ ] 全片稀疏网格已看；每个歧义区间有密帧；关键瞬间有原分辨率单帧
- [ ] 频谱 + RMS + BPM 可信度三检完成
- [ ] 每个 RMS 峰有画面成因；每个关键动作有音频印证
- [ ] 画外元素（手/袖/车头/道具）已归并到行动者并登记入画时间
- [ ] 单通道证据已标推测或已提问

### 剧情层
- [ ] 每事件有 trigger→action→reaction，相邻事件残余动量衔接
- [ ] 液体/面罩/杯瓶/头发干湿有完整状态演化
- [ ] N-beat 重复结构已提炼进 editing
- [ ] 每个定格四要素齐全，定格外无特效残留

### H3 格式层
- [ ] 字段名与顺序符合 02 号文件（Ref2VA 符合 shot-syntax 六段式），无自创字段
- [ ] `[Shot 1]` 无时间戳，其后严格递增且只标状态变化；Ref2VA 两位小数
- [ ] 三层声音不串；无 BGM 时 explicit silence / N/A
- [ ] 每个运镜写了动机，negative 列了禁用运镜与风格
- [ ] prompt 本体全英文，无中文残留
- [ ] I2VA：有锚定句与 visual_anchor，省略环境/灯光文本；标签语义六段一致
- [ ] 时长与 ffprobe 误差 ±0.02；镜头数=切点数+1
- [ ] 对话/歌词用 `<d>[Language] text</d>`；不写 copyrighted 歌词/商标

### 换角色附加
- [ ] 冻结层与底本逐字一致（随机抽 3 时间戳比对）
- [ ] 只改 subject / physics / 被带到的服装词
- [ ] 动作兼容性问题已处理；专属道具按入画纪律分级
- [ ] 动漫造型已转真人 cos；替换对照表完整、连带改动已声明

## 4. 交付形态

1. 中文反推报告（片型/场景/人物/因果链/剪辑特效/声音结论/推测项）
2. 英文 H3 完整 prompt（代码块，便于整段复制）
3. 换角色附中文对照表
4. 存盘 `<video-stem>_h3_prompt.md` 于视频同目录，并在回复打印最终文本块
5. 说明可选增强（I2VA 首帧锁定、定格关键帧导出、配乐字段替换），不擅自叠加
